## 问题现象

准备下载 GGUF 模型时，最担心的是文件下载几个小时，启动 `llama.cpp` 才发现显存不足。模型能否全量放进显卡，不能只看“7B、13B”这些参数量，还要同时看量化等级和目标上下文长度。

## 根本原因

GGUF（GPT-Generated Unified Format）模型的显存占用主要由三部分组成：

```text
显存需求 ≈ 模型权重 + KV cache（键值缓存）+ runtime overhead
```

模型权重可以先用这个公式估算：

```text
权重体积 ≈ 参数量 × 每参数字节数
```

量化等级越高，单个参数占用越多，模型文件通常也越大。KV cache 用来保存上下文推理过程中的键和值，会随着上下文长度、模型层数和并发批量增长。`n_ctx` 越大，KV cache 越大；长上下文模型即使权重能装下，也可能因为 KV cache 爆显存。

runtime overhead 是运行时缓冲区、临时计算空间、CUDA 工作区等额外开销，通常至少预留 **0.5-1GB**。不同模型架构、llama.cpp 版本、GPU 后端和上下文配置都会造成差异。

口诀：**权重 + KV + overhead，文件大小是基准。**

## 解决方案

### 方法一：先按量化等级估算权重

下面的系数是快速估算值，实际应以 GGUF 文件大小和启动日志为准：

| 量化等级 | 每参数约占用 | 适合的快速估算 |
|---|---:|---:|
| Q4_K_M | **0.55-0.65 字节** | 参数量 × 0.6 |
| Q5_K_M | **0.65-0.75 字节** | 参数量 × 0.7 |
| Q6_K | **0.80-0.90 字节** | 参数量 × 0.85 |
| Q8_0 | **1.00-1.10 字节** | 参数量 × 1.05 |
| F16 | **2.00-2.10 字节** | 参数量 × 2.1 |

例如，常见模型可以这样看：

| 模型规模与量化 | 权重体积约值 | 建议预留显存 |
|---|---:|---:|
| 7B Q4_K_M | **约 4.4GB** | **约 6GB** |
| 13B Q4_K_M | **约 8GB** | **约 10-11GB** |
| 70B Q4_K_M | **约 40-45GB** | **约 42-48GB 以上** |

这里的建议预留已经粗略包含 **1-2GB KV cache** 和 **0.5-1GB runtime overhead**。如果上下文从 4K 提升到 32K，KV cache 可能成为主要增量，不能继续只按模型文件大小判断。

### 方法二：显存不够时减少 GPU offload 层数

`-ngl` 降低后，只有部分层放入 GPU，剩余层在 CPU 和内存中运行。显存会下降，但速度通常也会变慢。可以从较小的层数开始逐步增加，例如：

```bash
llama-cli -m model.gguf -ngl 20 -p "test"
```

具体能放多少层，取决于模型层数和每层大小。不要把“层数比例”直接当成“显存比例”，因为 KV cache 和运行时缓冲区仍可能占用显存。

### 方法三：改用纯 CPU 模式

显卡确实装不下时，可以把 GPU offload 关闭：

```bash
llama-cli -m model.gguf -ngl 0 -p "test"
```

此时主要消耗系统内存，而不是显存。系统内存至少要能容纳模型文件、CPU 推理缓冲区和操作系统开销；实际运行通常需要比文件大小更多的内存。

下载前还可以直接查看文件大小：

```bash
ls -lh model.gguf
```

文件大小是估算权重体积最可靠的第一步，但不是最终显存需求。

## 验证是否解决

下载模型后，可以先尝试全量 offload：

```bash
llama-cli -m model.gguf -ngl 999 -p "test"
```

`-ngl 999` 会请求尽可能多地把模型层放入 GPU。运行另一个终端观察峰值显存：

```bash
nvidia-smi
```

如果启动时报 CUDA out of memory，或显存持续接近上限，就降低 `-ngl`，同时减少 `-c`（上下文长度）等配置，再重新测试。启动日志中的模型加载信息和实际峰值，比单纯套用参数量表更可信。

## 常见问题 FAQ

### 显存和系统内存怎么分工？

GPU 负责被 offload 的模型层、GPU 版 KV cache 和计算缓冲区；CPU 内存负责未 offload 的模型层、CPU KV cache 以及程序本身。`-ngl` 越低，显存压力越小，但系统内存和 CPU 计算压力越大。

### 70B 模型需要多大显存？

以 Q4_K_M 为例，70B 权重通常约 **40-45GB**，还要加 KV cache 和 runtime overhead。想在单张消费级显卡上全量运行，通常不现实；可以使用多卡、降低 `-ngl`，或直接采用 CPU/混合推理。Q8 和 F16 会进一步显著增加需求。

### 模型文件大小不等于显存占用吗？

不等于。文件大小主要反映权重体积，显存还包括 KV cache、临时缓冲区和 CUDA 运行时开销。相反，降低 `-ngl` 时，模型文件仍需完整保存在磁盘上，但只有部分权重进入显存。
