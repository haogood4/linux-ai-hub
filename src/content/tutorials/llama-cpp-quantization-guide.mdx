## 问题现象

同一个 GGUF 模型，Hugging Face 下载页可能同时提供 `Q2_K`、`Q3_K_M`、`Q4_K_M`、`Q5_K_S`、`Q8_0` 等十几个文件。它们都能被 llama.cpp 加载，但文件大小、显存占用和输出质量不同，选错可能导致显存不足，或者回答质量明显下降。

## 根本原因

量化（quantization）会把模型权重从 FP16 等高精度格式压缩成 2、3、4、5、6 或 8 bit。位宽越低，模型越小、显存占用越少，但精度损失通常越大。

`K` 表示 k-quants，一类比早期统一低位量化更先进的分组量化算法。`S`、`M`、`L` 可以理解为不同的大小与精度取舍：通常 `S` 更省空间，`M` 更均衡，`L` 更偏向质量。它们不是简单地把所有层都使用同一个位宽。

| 量化 | 相对 FP16 体积 | 质量与适用场景 |
|---|---:|---|
| Q2/Q3 | 约 20%～35% | 最省显存，但复杂推理、代码和长文本容易退化 |
| Q4 | 约 30%～40% | 质量和资源的主流平衡点 |
| Q5/Q6 | 约 40%～50% | 更少损失，适合质量优先 |
| Q8 | 约 55%～65% | 接近 FP16，文件和显存占用较大 |

以 7B 模型为例，`Q4_K_M` 通常约 4.4GB，`Q8_0` 通常约 7～8GB；实际大小取决于模型架构和词表。运行时还要额外为 KV Cache、上下文和临时缓冲区留出显存。

## 解决方案

### 1. 显存紧张：Q4_K_S 或 Q3_K_M

显存低于 6GB 时，优先尝试 7B/8B 的 `Q4_K_S`，通常需要约 4～5GB 加上运行开销。若仍然不足，再降到 `Q3_K_M`，模型本体通常约 3～4GB，但代码生成、数学推理和长上下文质量会更容易下降。

### 2. 日常使用：Q4_K_M

`Q4_K_M` 是大多数用户的默认选择。7B/8B 模型配合 6～8GB 显存通常比较合适，适用于聊天、总结、翻译和一般代码辅助。

```bash
llama-cli -m llama-2-7b-chat.Q4_K_M.gguf -p "请用三句话解释什么是量化模型。" -n 50
```

### 3. 追求质量：Q5_K_M

显存达到 8GB 以上，或者更在意代码、结构化输出和复杂推理，可以选择 `Q5_K_M`。7B 模型通常需要约 5～6GB 模型显存，再加上下文和程序开销。

### 4. 接近原精度：Q8_0

显存约 10GB 或更高时，可以使用 `Q8_0`。它适合评测、对比实验和质量优先的场景，但速度不一定比 Q4 更快，显存带宽和模型装载时间也可能成为瓶颈。若显存充足，还可以直接考虑 FP16。

## 验证是否解决

先观察显存是否接近上限：

```bash
nvidia-smi
```

再固定提示词和生成长度，对比不同量化的 prompt eval 与生成速度：

```bash
llama-cli -m llama-2-7b-chat.Q4_K_M.gguf -p "解释 TCP 和 UDP 的区别，并给出适用场景。" -n 128 -t 8
llama-cli -m llama-2-7b-chat.Q8_0.gguf -p "解释 TCP 和 UDP 的区别，并给出适用场景。" -n 128 -t 8
```

查看输出中的 `prompt eval` 和 `生成 tokens/s`。同一硬件、同一上下文、同一线程数下，Q4 通常比 Q8 更省显存，速度也可能更高，但具体数值必须以本机实测为准，不能直接套用其他机器的数据。

如果想要更客观的量化对比，可以用困惑度（perplexity）工具测量。注意：不同版本的 llama.cpp 工具名可能不同（老版本叫 `perplexity`，新版叫 `llama-perplexity`），具体以你安装的 llama.cpp 版本里实际的可执行文件为准：

```bash
llama-perplexity -m llama-2-7b-chat.Q4_K_M.gguf -f wiki.test.raw
llama-perplexity -m llama-2-7b-chat.Q8_0.gguf -f wiki.test.raw
```

实测记录应至少包含：量化版本、模型文件大小、最大显存、prompt eval 速度、生成速度和 perplexity。通常 Q8 的困惑度更接近 FP16，Q4_K_M 则在体积和质量之间取得较好平衡。不同模型、数据集和 llama.cpp 版本的绝对值不能横向照搬。

显存实在不够时，启用 CPU offload，把部分层放到内存运行；也可以减小上下文长度，或继续使用更低量化。CPU offload 能解决装载失败，但通常会降低速度。

**一句口诀：显存紧张 Q4_K_S，日常首选 Q4_K_M，追求质量 Q5_K_M，接近原精度 Q8_0。**

## 常见问题 FAQ

### Q2 和 Q4 精度差多少？

没有适用于所有模型的固定百分比。Q2 的体积更小，但在长文本、代码、数学和多轮对话中更容易出现退化；Q4_K_M 通常是更稳妥的起点。若 Q4 能装下，不建议为了节省少量空间直接降到 Q2。

### Q8_0 和 FP16 有什么区别？

`Q8_0` 仍然是量化格式，每个权重使用约 8 bit，并保留分组缩放信息；FP16 每个权重使用 16 bit。Q8 通常接近 FP16 的输出质量，但并不等价，文件和显存占用也更大。

### 同一模型的不同量化版本在哪下载？

优先在模型作者或可信量化发布者的 Hugging Face 仓库中下载，确认模型架构、聊天模板和文件校验信息一致。不要把不同底模或不同微调版本的量化文件混在一起。更多 llama.cpp 部署细节见 [llama.cpp 推理完全指南](/tutorials/llama-cpp-inference)。
