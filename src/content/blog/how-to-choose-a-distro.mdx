# 第一次装 Linux，别在几百个发行版里迷路：Ubuntu、Fedora、Arch 三选一

## 写在前面：选择范围其实只有三个

你打开搜索引擎，看到 Ubuntu、Fedora、Arch、Linux Mint、openSUSE、Manjaro、NixOS……再看几篇对比文章，发现每个作者推荐的都不一样。你本来只是想装个 Linux，最后却开始研究桌面截图、软件源速度和发行版哲学。

先把范围缩小：第一次装 Linux，优先只在 **Ubuntu、Fedora、Arch** 里选。

3 分钟决策树如下：

```text
if 你最在意省心、教程多、遇到问题容易搜索:
    选择 Ubuntu
elif 你希望软件较新，同时不想自己维护太多系统细节:
    选择 Fedora
elif 你愿意阅读文档、希望理解并掌控系统:
    选择 Arch
```

也可以直接看表：

| 你的优先级 | 推荐发行版 | 适合的人 |
|---|---|---|
| 省心、资料多、少折腾 | Ubuntu | 第一次装 Linux，想先把工作跑起来 |
| 追新、桌面体验现代 | Fedora | 想用较新的内核、桌面和开发工具 |
| 掌控、学习系统原理 | Arch | 愿意自己安装、配置和排查问题 |

如果你仍然无法决定，直接选 Ubuntu。它不是所有场景下都最好，但作为第一次实机安装的起点，出问题时最容易找到对应资料。以后不适合，再换 Fedora 或 Arch，成本没有你想象中高。

## 发行版到底在比什么

发行版（Distribution）可以理解为：把 Linux 内核、软件、安装器、更新机制和默认配置打包在一起的一套操作系统。

它们真正的差异，主要集中在四个要素。

### 1. Linux 内核

内核是操作系统管理硬件、进程、内存和文件的核心。Ubuntu、Fedora、Arch 都使用 Linux 内核，只是版本和默认配置不同。

新内核可能更早支持新硬件，也可能带来新的驱动问题。老一点的内核通常更保守，适合希望系统稳定运行的人。

第一次安装时，你不需要因为“内核版本”纠结太久。你的显卡、无线网卡和蓝牙能正常工作，比版本号更重要。

### 2. 包管理器

包管理器（Package Manager）就是帮你查找、安装、更新和删除软件的工具。

三者常用命令不同，但做的是同一件事：

| 发行版 | 包管理器 | 安装软件 | 更新软件索引 |
|---|---|---|---|
| Ubuntu | `apt` | `sudo apt install htop` | `sudo apt update` |
| Fedora | `dnf` | `sudo dnf install htop` | `sudo dnf makecache` |
| Arch | `pacman` | `sudo pacman -S htop` | `sudo pacman -Sy` |

实际操作可以这样验证：

```bash
# Ubuntu 22.04
sudo apt update
sudo apt install -y htop
htop --version
```

```bash
# Fedora 39
sudo dnf makecache
sudo dnf install -y htop
htop --version
```

```bash
# Arch 2024.01
sudo pacman -Sy --noconfirm htop
htop --version
```

软件包名称相同，并不代表三个系统完全一样，但常用开发工具、浏览器、编辑器和办公软件通常都能找到。真正影响你的，往往是安装命令、软件版本和默认配置，而不是“能不能用”。

### 3. GNOME 桌面环境

桌面环境（Desktop Environment）就是你看到的窗口、任务栏、设置中心和文件管理器。

Ubuntu 和 Fedora 默认通常使用 GNOME 桌面环境，但 Ubuntu 会加入自己的界面调整。Arch 默认安装内容更少，桌面需要你自己选择和配置。

这意味着：你喜欢某个桌面，不一定要更换整个发行版。Ubuntu、Fedora、Arch 都可以安装 GNOME、KDE Plasma 等桌面环境。

### 4. 更新节奏

更新节奏决定了系统多久收到新软件和新功能。

- **Ubuntu**：有长期支持版本，软件变化相对保守，适合稳定使用。
- **Fedora**：更新较快，通常能较早使用新内核和新桌面。
- **Arch**：滚动更新，也就是软件一有新版就推送，不需要等待下一代大版本。

更新越快，不代表一定越好。新版本可能修复硬件问题，也可能让某个旧插件暂时失效。你需要根据自己的时间和容错程度选择。

## 新手决策路径：省心、追新还是掌控

### 选择 Ubuntu：你只想尽快开始使用

Ubuntu 适合以下情况：

- 你第一次安装 Linux；
- 需要中文教程和搜索结果；
- 想安装开发环境、浏览器、办公软件；
- 不想花时间理解每个系统组件。

Ubuntu 的优势是资料广、默认配置完整、安装器相对容易理解。很多软件官方文档也会优先提供 Ubuntu 的安装命令。

如果 Ubuntu 不适合你，常见原因是桌面风格不喜欢、软件版本偏旧或某些硬件支持不理想。你可以先换一个桌面环境，也可以把同一台虚拟机换成 Fedora；个人文件和大部分开发配置都能迁移。

官方文档：[Ubuntu Documentation](https://ubuntu.com/tutorials)

### 选择 Fedora：你想用较新的系统组件

Fedora 适合以下情况：

- 你想体验较新的 GNOME、内核和开发工具；
- 你愿意偶尔处理软件更新带来的变化；
- 你希望系统默认配置比较干净；
- 你对企业 Linux 生态也有兴趣。

Fedora 的包管理器是 `dnf`，软件仓库维护方式和 Ubuntu 不同。某些网上教程只给出 `apt` 命令时，你需要查找 Fedora 对应写法。

如果 Fedora 的更新节奏让你觉得麻烦，可以改用 Ubuntu 的长期支持版本。已经投入的时间不会浪费：终端、Git、Python、容器和编辑器的使用方式基本不变。

官方文档：[Fedora Docs](https://docs.fedoraproject.org/)

### 选择 Arch：你把学习系统本身当成目标

Arch 适合以下情况：

- 你愿意按照文档一步步安装；
- 你想知道系统每个组件为什么存在；
- 你能接受滚动更新；
- 遇到问题时愿意先看日志和官方 Wiki。

Arch 的优点是系统组成清晰、可定制程度高，Arch Wiki 也是非常有价值的技术资料来源。代价是安装和维护需要更多判断，不能只依赖“下一步”。

如果 Arch 让你花太多时间排错，可以先换 Ubuntu 或 Fedora，把 Linux 当作工作工具使用。以后仍然可以在虚拟机或备用硬盘上继续学习 Arch。

官方文档：[Arch Wiki](https://wiki.archlinux.org/)

### 中文资料怎么选

中文资料丰富度通常可以这样理解：

| 发行版 | 中文资料 | 适合的查资料方式 |
|---|---|---|
| Ubuntu | 最丰富 | 先搜 Ubuntu 版本，再看官方文档和社区讨论 |
| Fedora | 较丰富 | 优先看 Fedora Docs，再参考通用 Linux 资料 |
| Arch | 安装经验多，维护资料需甄别 | 优先看 Arch Wiki，中文文章只作辅助 |

不要只复制搜索结果里的命令。先确认命令对应的发行版和版本。`apt`、`dnf`、`pacman` 不能互换，教程里的配置文件路径也可能不同。

## 两个常见坑别踩

### 不要只为颜值选择冷门发行版

桌面截图很容易让人心动，但截图展示的是主题、图标和壁纸，不是驱动支持、更新方式和故障排查成本。

很多冷门发行版并没有独立的软件生态，只是在 Ubuntu、Fedora 或 Arch 的基础上更换了桌面和默认配置。你获得的是一套外观，承担的却可能是更少的教程和更慢的问题反馈。

如果你已经因为外观装了冷门发行版，发现资料难找，不需要从头学习。先确认它的上游基础，再直接参考对应的 Ubuntu、Fedora 或 Arch 文档；如果仍然不顺手，就换回上游发行版。

### 不要在虚拟机里反复纠结

虚拟机的价值是验证工作流，不是模拟全部真实硬件。虚拟机无法完全代表你的显卡、无线网卡、触控板和休眠功能。

你可以在 `/try/virtualbox` 参考创建虚拟机的步骤。每个发行版只测试：

1. 能不能正常启动和关机；
2. 常用软件能不能安装；
3. 你的工作流能不能完成。

测试通过就做决定，不要因为 GNOME 的一个图标间距反复重装五次。外观可以调整，安装习惯和文件布局也可以迁移。

## 20 分钟验证法

### 第 1 步：准备虚拟化工具

如果你使用 Linux 作为宿主机，可以安装系统自带的虚拟化工具。

Ubuntu 22.04：

```bash
sudo apt update
sudo apt install -y qemu-kvm libvirt-daemon-system virt-manager
sudo systemctl enable --now libvirtd
```

Fedora 39：

```bash
sudo dnf install -y @virtualization
sudo systemctl enable --now libvirtd
```

Arch 2024.01：

```bash
sudo pacman -Syu --noconfirm qemu-desktop libvirt virt-manager
sudo systemctl enable --now libvirtd
```

如果你使用 Windows 或 macOS 作为宿主机，可以使用 VirtualBox，具体流程见[虚拟机试用指南](/try/virtualbox)。下载镜像时，优先从 Ubuntu、Fedora 或 Arch 官方页面获取，不要从不明网盘下载。

### 第 2 步：给每个发行版相同的测试条件

虚拟机可以设置 4 GB 内存、2 个 CPU 核心和 30 GB 虚拟磁盘。这个配置不是性能标准，只是让三者处在相近条件下。

安装完成后，分别运行对应命令安装 `htop`：

```bash
# Ubuntu
sudo apt update && sudo apt install -y htop
```

```bash
# Fedora
sudo dnf install -y htop
```

```bash
# Arch
sudo pacman -Syu --noconfirm htop
```

### 第 3 步：只看三件事

**第一，看硬件和桌面是否正常。**  
检查窗口缩放、中文输入、声音、网络和文件管理器。虚拟机里的显卡表现不具备代表性，但桌面操作是否顺手仍然可以判断。

**第二，看软件安装是否符合直觉。**  
安装浏览器、编辑器或 Git，记录你是否能看懂软件来源和更新方式。命令行可以验证 Git：

```bash
git --version
```

如果系统没有 Git，再用对应的包管理器安装：

```bash
# Ubuntu
sudo apt install -y git
```

```bash
# Fedora
sudo dnf install -y git
```

```bash
# Arch
sudo pacman -S --noconfirm git
```

**第三，看你是否愿意维护它。**  
打开系统更新界面，查看软件源设置，再搜索一次常见错误。你不需要解决所有问题，只要判断遇到问题时能否找到可信资料。

如果 20 分钟后仍然纠结，选择 Ubuntu。验证的目标是排除明显不适合，不是找出理论上最完美的系统。

## 实机安装前的兜底判断

虚拟机通过后，实机安装前先备份重要文件。安装器涉及真实磁盘时，磁盘分区和启动项操作可能造成数据丢失；不要在没有备份的情况下删除、格式化或覆盖现有系统。

首次实机安装建议使用发行版默认方案，并保留一个能正常联网的恢复路径。遇到显卡、无线网卡或休眠问题时，先记录硬件型号和日志，再搜索对应版本的官方文档，不要连续执行来历不明的修复脚本。

你也不需要一次性配置完整。先安装系统、浏览器、编辑器和 Git，确认能工作，再逐步调整字体、主题、快捷键和开发环境。

## 记住这一点就够了

发行版选择不是永久绑定。你的个人文件可以放在独立目录或同步服务中，Shell 配置、Git 配置、编辑器设置和项目代码都能导出。开发语言和工具也通常有跨发行版安装方式。

真正昂贵的是把时间耗在选择上，而不是用半天换一个发行版。先用下面这句口诀做决定：

```text
想省心，选 Ubuntu；
想追新，选 Fedora；
想掌控，选 Arch；
装上后不合适，就换回另外两个。
```

开始使用后的真实体验，比安装前的发行版排名更有参考价值。相关版本和桌面选项可以继续在[发行版推荐](/distros)和[发行版选择器](/distros/picker)查看。
