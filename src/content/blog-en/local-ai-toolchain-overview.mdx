# Local AI toolchain map: get something running first, then upgrade layer by layer

It sounds like a tinkering hobby, but it is already mature. Local AI in 2026 is no longer just "download a model, open a terminal": chat, images, video, speech, knowledge bases and automation have formed a fairly clear toolchain. This article is a map — not a push to install everything — so you know what each piece is and when you actually need it.

## 1. Model runtime: the foundation of everything

The first step of local AI is "getting a model to run". This layer is called the runtime. There are two mainstream routes:

- **Ollama**: installed with one command, usable out of the box — `ollama run qwen3` starts a chat. It suits beginners and daily use, and is the default backend most GUI tools connect to.
- **llama.cpp / vLLM**: lower-level, more controllable. llama.cpp focuses on single-machine inference and quantization (GGUF format); vLLM targets high-concurrency serving (OpenAI-compatible API, multi-user throughput).

**When you need Ollama:** if you want to chat, summarize or write code on a personal machine, or quickly verify whether a model fits your needs, install Ollama first. See [Ollama local deployment](/tutorials/ollama-local-deploy).

**When you need llama.cpp:** when you run special model formats, study quantization parameters, fine-tune on resource-limited devices, or want to embed inference into your own program. See [llama.cpp inference](/tutorials/llama-cpp-inference).

**When you need vLLM:** once the model and business needs are confirmed, and you must serve many concurrent requests or run a stable internal inference service. See [vLLM serving](/tutorials/vllm-serving).

## 2. Chat interface: a shell for the model

The command line runs models, but most people want a GUI. Open WebUI is the most popular choice: chat, file uploads, multi-model switching and local knowledge base management in one place, accessible from a browser. See [Open WebUI deployment](/tutorials/open-webui).

**When you need it:** you do not want to work through the command line every time, or you need multi-user sharing, file Q&A, session history and model management.

## 3. Image and video: creative models

- **Stable Diffusion WebUI**: the most mature, with a rich plugin ecosystem — the natural entry point for text-to-image. See [Stable Diffusion](/tutorials/stable-diffusion).
- **ComfyUI**: node-based workflows with high freedom — the tool for advanced tuning, batch generation and reproducing community workflows. See [ComfyUI basic workflows](/tutorials/comfyui-basic-workflow).
- **AI video generation**: open-source video models are usable in 2026; Wan, LTX and others can be tried on consumer GPUs.

**When you need it:** text-to-image, image-to-image, inpainting, upscaling or common plugin features with a familiar interface — pick Stable Diffusion WebUI; if you combine multiple models, fix complex flows or batch-generate, learn ComfyUI.

Whether video models run smoothly depends on VRAM, model version, resolution, frame count and workflow configuration — do not judge hardware by model name alone. Start with smaller parameters and short clips. Entry path: [AI video generation](/tutorials/ai-video-generation).

## 4. Speech: hear you, talk to you

- **TTS**: open-source projects like CosyVoice produce near-human voices and can clone a voice.
- **ASR**: Whisper and similar mature solutions handle recognition.

**When you need it:** voice assistants, subtitles, podcasts, audio content or voice interaction. If you only do text chat, skip this layer entirely. See [local TTS](/tutorials/local-tts).

## 5. Knowledge base and automation: let AI use your materials

- **RAG knowledge base**: split documents into chunks, vectorize, retrieve, then let the model answer with citations — solving "the model does not know my private material". See [RAG knowledge base](/tutorials/rag-knowledge-base).
- **Dify**: build AI apps visually — wiring models, knowledge bases and tool calls into workflows without writing code. See [Dify visual AI platform](/tutorials/dify-visual-ai-platform).
- **Function Calling / MCP**: let the model call external tools (weather, file operations, APIs) — the step from "chatting" to "doing work". See [Function Calling and MCP](/tutorials/function-calling-mcp).

**When you need RAG:** you keep asking about your own materials and want answers that cite documents. Pure chat or writing does not require a knowledge base first.

**When you need Dify:** you build Q&A apps, customer-service flows or document-processing flows for others, not just chat in a personal window.

**When you need Function Calling or MCP:** the model must perform actions, not just generate text.

## 6. Hardware and containers: the base

- VRAM decides how large a model you can run; GPU memory, system RAM, disk space, driver version and cooling all matter. Model files can eat a lot of disk, and video/image workflows produce caches and intermediate files. Start by checking [hardware reference](/hardware).
- Docker isolates services (Ollama, Open WebUI, vector DB, Dify), reduces dependency conflicts and eases migration — but it does not fix GPU driver problems. GPU containers require compatible host drivers, container runtime and framework versions; keep config and data backups before upgrading. See [Docker GPU containers](/tutorials/docker-gpu-containers).

Not familiar with Linux? Use native apps or Docker Desktop on your current system to validate needs first, then consider a server later. The [Linux try-out guide](/blog/try-linux-without-risk) suits readers who want low-risk exposure.

## How to start

Do not chase completeness. A gradual path:

1. Install Ollama + Open WebUI first — solve "can chat".
2. Add Stable Diffusion or ComfyUI when you need images.
3. Add RAG / Dify when materials pile up.
4. Only then speech, video and MCP as advanced items.

Validate each layer before adding the next; design permission boundaries, logs and error handling once the system has a clear purpose.

The local AI toolchain is a map, not a checklist: install Ollama first, then add interfaces, image generation, knowledge bases, speech and MCP as needs appear. One layer at a time.
