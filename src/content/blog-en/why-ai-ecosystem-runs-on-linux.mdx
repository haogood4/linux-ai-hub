# Why do AI tool docs always put Linux first?

Many people hit the same scene the first time they seriously touch AI tools: you search for tutorials on Ollama, PyTorch, Stable Diffusion or vLLM, the page opens, and the example environment is almost always Linux. This article does not try to talk you into switching systems — it explains where this phenomenon comes from and what it means for your choices.

## Reason 1: the server market was already Linux's territory

AI training and inference run on servers, and the server market has long been dominated by Linux. Most cloud providers' default instance images, most open-source projects' CI environments, and the base layer of most container images are Linux. This ecosystem is the result of decades of accumulation, not something one company pushed:

- Linux is free and free of license-audit pressure, suitable for large-scale deployment.
- The kernel is stable and can run unattended (servers usually have no monitor).
- Package managers and configuration management tools are mature, ideal for automated operations.

When AI framework developers write docs and run tests for a "target environment", they first cover the environment they actually use — Linux. Windows and macOS support is usually an addition, not the starting point.

## Reason 2: the AI toolchain was born on Linux

The bond between modern AI frameworks and Linux runs deep historically:

- **PyTorch and TensorFlow**: official binaries ship for Linux first, with the most complete features and earliest GPU support.
- **CUDA (NVIDIA's GPU computing platform)**: official drivers and toolchains are most stable on Linux; many low-level optimizations in deep learning land on Linux first.
- **Containerized deployment**: Docker and Kubernetes themselves originated on Linux, and AI services are almost always shipped as containers — exposing GPUs to containers with the NVIDIA container toolkit (nvidia-container-toolkit) is the standard way to deploy AI services.

This means: most AI problems you run into have already been answered once in the Linux context.

## Reason 3: local inference is becoming a new scenario for ordinary users

In recent years, running large models locally (Ollama, llama.cpp) and generating images locally (Stable Diffusion, ComfyUI) moved AI from "cloud service" into personal computers. For these scenarios, Linux's appeal only grows:

- **Scriptable**: from driver installation to running models, everything is reproducible on the command line — copy a tutorial and it works.
- **Resource transparency**: VRAM, memory and CPU usage can be inspected precisely with commands; debugging performance is straightforward.
- **Data stays on your machine**: local inference exists for privacy and offline use, and Linux has less of the "background service silently phones home" uncertainty.

For ordinary users, this does not mean "you must install Linux". On Windows, WSL2 runs most AI tools; macOS users have Metal acceleration. But if you want to reproduce results by following tutorials step by step, the Linux environment usually offers the least friction.

## What this means for you

- **Just want to try AI**: keep using the system you know — WSL2 or the official Windows installer is fine.
- **Serious about AI / deploying services**: give Linux a chance — a [virtual machine](/try/virtualbox) or dual boot starts at zero risk.
- **Buying a new computer**: if the machine is primarily for AI use, choosing Linux at install time saves detours later.

## Summary

The bond between the AI ecosystem and Linux is rooted in the historical structure of the server market and the natural kinship of open-source toolchains — not some exclusive agreement. It will not force you to use Linux, but it makes people who "want fewer hassles" choose Linux more and more.
