## 写在前面

只有 16GB 内存、没有独立显卡，或显存不足 8GB，并不等于无法运行本地模型。`llama.cpp` 的定位是一个面向 GGUF 模型的轻量推理运行时：通过量化降低内存需求，并允许用户直接控制 CPU、GPU 与上下文等参数。它适合想把模型真正跑在自己设备上、同时接受命令行和参数调优的人。可先参考[llama.cpp 推理教程](/tutorials/llama-cpp-inference)。

## 技术亮点与实测关注点

它支持 Windows、Linux、macOS 及多种嵌入式平台；GGUF 量化档位从高精度到低占用覆盖 Q8、Q6、Q5、`Q4_K_M` 等。以常见 7B/8B 模型为例，`Q4_K_M` 通常能把权重压到约 4—5GB，但实际内存还会受到上下文、批处理和运行时开销影响，不能只看文件大小。命令中的 `-ngl` 控制卸载到 GPU 的层数，显存不足时可降低它，甚至设为 CPU 推理。

`llama-server` 提供 OpenAI 兼容 API，意味着本地模型可以替代部分云端接口，接入编辑器、脚本或现有应用；代价是模型文件、并发能力和服务稳定性都由本机承担。量化选择可结合[显存量化](/blog/vram-quantization-gguf)理解，但不同模型的量化质量不能简单横向等同。

## 适用场景与边界

无独显用户可用较小模型完成问答、总结和代码辅助；量化研究者能比较档位、上下文和卸载层数；嵌入式开发者则可获得可裁剪、可离线部署的运行时。局限同样明确：命令行门槛高，GGUF 文件需要自行管理，CUDA、Metal 等 GPU 后端的构建和兼容性也可能耗时。不适合追求云端级并发、超长上下文或大模型质量的人。

一句话选型：要开箱即用选 Ollama，要控制量化、硬件分配和 API 细节选 llama.cpp。
