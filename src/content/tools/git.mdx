为什么 Git 能统治版本控制领域？它为 Linux 内核开发而生，将版本库完整历史放到每位开发者本地，改变了集中式系统依赖单一服务器的协作方式。断网时仍可查看记录、创建提交，服务器故障也不等于历史丢失。

## 核心亮点与生态

Git 的分支只是轻量引用，创建、切换和合并成本低，适合并行开发与代码审查。在现有仓库可实测：`git status` 查看状态，`git log --oneline --graph --all` 浏览分支历史，`git diff --staged` 检查暂存区 (Staging Area) 内容。

GitHub、Gitee 将 Git 扩展为托管、评审和自动化协作平台。Git 跨平台，但 Linux 下命令行、Shell 和权限模型衔接最自然；可查阅 [Pro Git 中文版](https://git-scm.com/book/zh/v2) 与 [Git 官方文档](https://git-scm.com/docs)。

## 谁应该掌握

需要多人协作、追踪改动、回退版本或参与开源项目的开发者，Git 基本属于必修工具。个人项目同样受益：提交记录能解释“何时、为何修改”，分支可隔离实验功能。

## 门槛与局限

Git 难点不在提交本身，而在工作区、暂存区、引用及变基 (Rebase) 的关系；`reset`、`revert`、`rebase` 作用不同，误用可能改写共享历史。命令行报错也常要求理解当前状态。兜底方案是使用 VS Code、GitHub Desktop 等图形客户端观察提交图，再逐步补齐命令行能力。

口诀：Git 上手有门槛，本地历史与灵活分支让它值得学。
